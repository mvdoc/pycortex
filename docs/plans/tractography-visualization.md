# Tractography visualization in pycortex — implementation plan

Repo copy of the approved plan (also at the Claude plan file). Subagents: read this file first.

## Context

pycortex has two data axes (`VolumeData`/`VertexData`) and nothing for streamlines. The goal is to load pyAFQ output (TRX files) into a first-class container and render the streamlines in the WebGL viewer together with a (partially transparent) cortical surface carrying an overlay. Work is split into 4 small PRs plus an optional follow-up bucket, so each is reviewable alone and two tracks can run in parallel. No PR is opened without the user's approval; everything is verified locally first.

Decisions already made with the user:
- **Reader**: depend on `trx-python` as an optional extra (`pycortex[tractography]`). It requires Python ≥ 3.11; CI still runs 3.10, so the module imports lazily and tests `pytest.importorskip("trx")`.
- **Alignment**: pyAFQ output is normally in the DWI/T1 RASmm space, which matches pycortex fiducial surfaces when the DWI is aligned to the T1. Loader accepts an optional 4×4 `xfm` for other cases.
- **Test data**: synthetic TRX generated in tests (curves derived from S1's fiducial surface, written with trx-python). No binary fixtures in git, no downloads in CI.
- **Realistic local verification data**: the user's own pyAFQ TRX is 200 GB and not usable yet, and FreeSurfer is not installed locally (so datasets shipping only a T1 + bundles, e.g. dipy's `fetch_bundles_2_subjects`, cannot get surfaces). Use instead pyAFQ's **HCP 16-bundle atlas in MNI space** (`AFQ.data.fetch.fetch_hcp_atlas_16_bundles`, figshare file 11921522, `Atlas_in_MNI_Space_16_bundles/bundles/*.trk`) overlaid on the **`fsaverage` subject already in `~/repos/pycortex_store`**. Alignment check done during planning: fsaverage is in MNI305 space (FreeSurfer wiki, CoordinateSystems); the wiki's MNI305→MNI152 RAS matrix is `[[0.9975,-0.0073,0.0176,-0.0429],[0.0146,1.0009,-0.0024,1.5496],[-0.0130,-0.0093,0.9971,1.1840],[0,0,0,1]]`, i.e. ≤ 1.6 mm translation and ≤ 0.3 % scale, and the store's fsaverage pial bounding box (x −69…70, y −105…69, z −48…79 mm) matches MNI152 brain extents. So the atlas bundles can be shown as-is; for exactness pass the inverse of that matrix as `xfm` (MNI152 → MNI305). Note: the store's `fsaverage/transforms/atlas/{matrices.xfm,reference.nii.gz}` are unfetched git-annex symlinks, so `db.get_xfm("fsaverage","atlas")` will fail until `git annex get` is run there — not needed for the tract overlay, which uses surface mm directly. Convert `.trk` → `.trx` with trx-python (`trx.io.load(trk, reference=MNI T1)` then `save`), or load `.trk` directly through the same `trx.io.load` path. The download (user-approved, size to be reported before fetching) happens in the user's environment, never in tests.

Facts from exploration that constrain the design:
- Fiducial surfaces are in T1 scanner RAS mm (`cortex/freesurfer.py:295-303`, `mris_convert --to-scanner`); the viewer uses surface coordinates directly as mesh positions (`shaderlib.js` only uses `volxfm` for texture lookup). So TRX RASmm positions need no transform when DWI is aligned to the T1.
- `dataset.normalize` passes any `Dataview` subclass through untouched (`cortex/dataset/dataset.py:212-221`); `Package.__init__` (`cortex/webgl/data.py:24-73`) branches on `Vertex`/`VertexRGB` vs volume and needs a new branch; `Package.reorder` (`data.py:89-105`) must skip tracts (no CTM reordering).
- Live server payloads go through Tornado handlers in `cortex/webgl/view.py` (`DataHandler` L480-511 serves in-memory bytes with Range support; routes L1025-1032); `MixerHandler` passes `json.dumps(metadata)` to `mixer.html`. `make_static` (L44-282) writes payloads to disk; `htmlembed.py` only inlines `<script>/<link>/<img>`.
- Three.js is **r69**: `THREE.BufferGeometry` + `addAttribute`, `THREE.Line(geom, mat, THREE.LinePieces)`, Uint32 index buffers work when `OES_element_index_uint` is present (`three.js:20337`), `object.renderDepth` exists for ordering, no `renderOrder`/`depthFunc`. `renderer.sortObjects = true` (`axes3d.js:82`): opaque objects draw before transparent ones.
- Surface material is created in `dataset.js:252-264` (`getShader`, **CRLF file**) with `transparent/depthWrite` coming from `opts` passed by `mriview_surface.js:401-412`. Fragment alpha is never modulated: both `Shaders.surface_vertex` (~L606-660) and `Shaders.surface_pixel` (~L820-885) end with `lights_phong_fragment`, which only touches `.xyz`. Existing `dataAlpha` uniform is overlay-vs-curvature opacity, not surface opacity (open issue #353 asks for exactly this).
- Uniform → dat.gui → Python plumbing: declare on `this.uniforms` in `mriview_surface.js:67-97`, auto-merged by `getShader`, exposed via `this.ui.add({name: {action:[uniform,"value",0,1]}})` (`mriview_surface.js:102-138`); `JSMixer.view_props` (`view.py:562-588`) enumerates surface controls dynamically so `_set_view(...)` and `save_3d_views` pick new sliders up for free.
- Face picking renders its own `THREE.Scene` containing only `surf.object` (`facepick.js:24-25`), so extra objects in `viewer.root` do not disturb hover/click.
- Surface morphing (`setMix`, `mriview.js:960`) moves the mesh to inflated/flat; tracts only make sense at mix = 0.
- Headless tests: `cortex/export/headless.py:headless_viewer`, skip via `testing_utils.has_playwright`; visual regression harness in `cortex/tests/test_visual_regression.py` (`_render_and_check_webgl_only`, refs in `cortex/tests/reference_images/<group>/`, LFS WebP, `REGENERATE_REFERENCE_IMAGES=1`). Chromium cannot launch inside the Claude Bash sandbox — the user runs browser tests; Claude inspects the live viewer through the built-in browser.
- `setup.py:120-138` already ships `resources/js/*.js`; a new JS file directly in `resources/js/` needs no packaging change.
- Open PRs touching the same JS: #695 (alpha/NaN handling), #708/#720 (shader displacement utility, bumpy flatmap), #715 (2-D vertex shader fix), #738 (depth profiles). PR3 edits the same fragment-shader tail as #695/#708 — keep the change to a two-line insertion to minimize conflicts.

## Design summary

### Data model — `cortex.Tractogram` (new `cortex/dataset/tractogram.py`)
`class Tractogram(Dataview)`, constructed from arrays, not tuples:
- `points`: `(N, 3) float32`, surface mm; `offsets`: `(M+1,) int64` (TRX convention, sentinel = N); `dpv: dict[str, (N,k)]`, `dps: dict[str, (M,k)]`, `groups: dict[str, int array]` (streamline indices), `subject`.
- Display attributes (Dataview-style kwargs): `color="orientation"` (default; per-segment |direction| RGB, the tractography standard) | `(r,g,b)` constant | `"dpv:<name>"` / `"dps:<name>"` scalar mapped through `cmap`/`vmin`/`vmax`; `alpha` (0–1), `linewidth` (px, WebGL clamps to 1 on most platforms — documented), `description`.
- `from_trx(path_or_TrxFile, subject, xfm=None, **display)` — uses `trx.io.load`; copies `streamlines._data`/`_offsets`, dpv/dps/groups into RAM (memmaps get closed); applies `xfm` (4×4 on RASmm) if given.
- Helpers: `__len__`, `lengths`, `select(idx)`, `get_group(name)`, `subsample(max_streamlines=None, step=None, seed=0)` (decimation for the viewer; pyAFQ outputs ~1–2 M points across bundles, ~50 MB non-indexed — fine, but big whole-brain tractograms need this), `vertex_colors()` → `(N,3) uint8` (all colormapping done in Python so the JS/shader side is trivial and reuses `Dataview.get_cmapdict` + matplotlib), `to_json(simple)` (metadata only: counts, groups, display state), `_write_hdf` → `NotImplementedError` (HDF5 in follow-ups).
- Exported from `cortex/dataset/__init__.py` and `cortex/__init__.py`; `pyproject.toml` gains `tractography = ["trx-python"]` extra and adds it to the `test` dependency group; mypy override for `trx.*`.

### Wire format viewer ⇐ Python (fixed now so PR1 and PR2 can proceed in parallel)
`metadata["tracts"] = {name: {subject, n_points, n_streamlines, alpha, linewidth, visible, groups: {gname: n}, urls: {points, offsets, colors}}}`; three little-endian binary buffers per tractogram: `points` float32 `(N,3)`, `offsets` uint32 `(M+1,)`, `colors` uint8 `(N,3)`. Live: `/tract/{name}/{buffer}`; static: `tracts/{name}_{buffer}.bin`. JS builds the segment index (`2·(N−M)` uint32) itself.

### Rendering
One `THREE.BufferGeometry` per tractogram: `position`, `color` attributes + Uint32 `index`; `THREE.Line(geom, THREE.LineBasicMaterial({vertexColors: THREE.VertexColors, transparent, opacity}), THREE.LinePieces)`; added to `viewer.root`. Opaque by default (alpha 1) so it renders before the transparent surface and writes depth. Hidden (or faded) when `mix > 0`. Fallback when `OES_element_index_uint` is missing: chunked Uint16 draw via `geometry.offsets` (r69 drawcall chunks) — implement only if the primary path fails on the user's GPU.

### Surface opacity
New uniform `surfaceAlpha` multiplied into `gl_FragColor.a` just before `lights_phong_fragment` in both surface shaders; material switched to `transparent:true, depthWrite:false` only while `surfaceAlpha < 1` (toggled in `Surface.prerender`) so the opaque default path is byte-identical to today. dat.gui slider `surface_opacity` in the surface folder (auto-exposed to Python via `view_props`), `webgl_viewopts.surface_opacity = 1.0` default in `cortex/defaults.cfg`. Tracts drawn inside the brain then show through; medial wall of the other hemisphere shows through too, which is the expected translucent look. A depth pre-pass (second mesh with `colorWrite:false`) is a fallback if two-layer artifacts are ugly — decided by looking, in PR4.

## PR sequence

Dependency graph: `PR1 ∥ PR3` → `PR2` (needs PR1; can start against the wire format as soon as PR1's API is agreed) → `PR4` (needs PR2 + PR3). Branch each PR off `main`; PR2 is based on PR1's branch and rebased after PR1 merges.

Suggested agent tiers (budget): Sonnet for PR1, PR3 and all tests/docs; Opus only for the Three.js r69 rendering code in PR2 and the compositing/visual-tuning in PR4. Review each PR once with the `pycortex-code-reviewer` agent (`/code-review` medium) before showing it to the user. The main session (this one) keeps the integration/visual checks with the built-in browser and does not re-implement what agents did.

### PR1 — `Tractogram` dataview + TRX loading (Python only) — Sonnet, serial start
Files: new `cortex/dataset/tractogram.py`; `cortex/dataset/__init__.py`, `cortex/__init__.py` (export); `pyproject.toml` (extra + test group + mypy override); new `cortex/tests/test_tractogram.py`; `docs/dataset.rst` short section.
Tests (importorskip trx): synthetic TRX fixture built from S1 fiducial (`cortex.db.get_surf("S1","fiducial")`, ~20 streamlines of ~30 points along vertex chains + a dpv scalar + a dps scalar + 2 groups) written via trx-python (`TrxFile.from_tractogram(nib.streamlines.Tractogram(...), reference=...)` — implementer verifies exact API against the installed version); round-trip `from_trx` → arrays/dpv/dps/groups equal; `xfm` applied; `vertex_colors` for orientation/constant/dpv/dps modes (shape, dtype, range, nan→transparent-ish consistent with `Dataview`); `subsample` invariants (offsets monotone, sentinel); `normalize(Tractogram)` passes through; `to_json` keys match the wire format above.
Definition of done: `uv run pytest cortex/tests/test_tractogram.py` green; mypy clean on the new module; `import cortex` still works without trx installed.

### PR3 — Surface opacity slider (JS + shader, independent) — Sonnet, parallel with PR1
Files: `cortex/webgl/resources/js/shaderlib.js` (uniform decl + `gl_FragColor.a *= surfaceAlpha;` in both surface shaders), `mriview_surface.js` (uniform, `surface_opacity` slider, prerender toggle of `transparent/depthWrite`), `cortex/defaults.cfg` (`[webgl_viewopts] surface_opacity = 1.0`), `cortex/webgl/view.py` only if `view_props` needs the name whitelisted (check L562-588 first), `docs/userguide/webgl.rst` one paragraph. Do **not** touch `dataset.js` unless unavoidable (CRLF).
Tests: headless (skip w/o Playwright) — open viewer with a `Vertex`, `handle._set_view(surface_opacity=0.3)` via `save_3d_views` or `headless_viewer`, screenshot, assert background color bleeds through where the brain is (compare a center-pixel region against the opaque render). Add a `surface_opacity` nonflat view to the visual regression parametrization (+ regenerate references, LFS).
Definition of done: opaque default renders pixel-identical to `main` (visual regression suite unchanged); slider works in the live viewer (user checks in browser); closes #353.

### PR2 — Streamline rendering in the WebGL viewer — Opus for JS, Sonnet for Python transport; after PR1 API is fixed
Python: `cortex/webgl/data.py` (`Package`: collect `Tractogram` views into `self.tracts` (bytes) + `self.tract_meta`; skip them in `reorder`; `metadata()` adds `tracts`; keep them out of `self.brains`/`images` so existing JS paths are untouched), `cortex/webgl/view.py` (`TractHandler` for `/tract/(.*)` mirroring `DataHandler` incl. Range; route registration; `make_static` writes `tracts/*.bin` and rewrites `urls`; `addData` learns to push tracts), `cortex/webgl/serve.py` untouched.
JS: new `cortex/webgl/resources/js/tractogram.js` (`mriview.Tractogram`: fetch the 3 ArrayBuffers with `XMLHttpRequest`/`fetch` (check what `surfload.js`/CTM loader uses for consistency), build geometry as in *Rendering*, dat.gui folder `tracts/<name>` with `visible`, `opacity`, per-group visibility later), `mriview.js` (`addTracts(meta)` called from the same place `setData`/surfaces are built from `metadata`; `root.add`; hide when `setMix(mix) > 0`; dispose on `rmData`), `cortex/webgl/template.html` `<script>` include (check `static.html` extends it). No new package_data needed.
Tests: `cortex/tests/test_webgl_tractogram.py` — `Package` metadata/buffer sizes without a browser; `make_static` writes the three `.bin` files with expected byte lengths; headless (skipped w/o Playwright) loads `[Vertex, Tractogram]`, waits for `viewer.loaded`, asserts `window.viewer.tracts[name].geometry.attributes.position.count == N` via `JSProxy` and takes a screenshot that differs from the tract-less render.
Definition of done: user opens the viewer locally with the HCP 16-bundle atlas on `fsaverage` + a Vertex overlay and sees bundles in anatomically plausible places (CST under motor cortex, arcuate lateral, CC midline); live and static (`make_static`) paths both work.

### PR4 — Integration, compositing and docs — Opus for compositing, Sonnet for example/docs; after PR2 + PR3
- Verify depth/blend interaction (tracts opaque + translucent surface) in the browser; tune: tracts `renderDepth`, `depthWrite` policy when tract `alpha < 1`, optional depth pre-pass if double-layer artifacts are bad; fade tracts with `mix`.
- `cortex.webgl.show([overlay, tractogram])` end-to-end docs: new `docs/tractography.rst` (loading, color modes, alignment/`xfm`, opacity, limits: 1 px lines, vertex counts, no quickflat), link from `docs/index.rst`; gallery example `examples/tractography/plot_tractogram.py` using synthetic streamlines on S1 (gallery must run without private data; if Sphinx-gallery needs a screenshot use `headless_viewer`).
- Visual regression: new `cortex/tests/reference_images/tracts/` group (synthetic tracts, opaque surface; translucent surface) via `_render_and_check_webgl_only`.
- `AGENTS.md`: two lines under "Data containers" and "WebGL viewer" about `Tractogram`, the `/tract/` handler and `tractogram.js`.

### Follow-ups (separate small PRs, not now)
HDF5 persistence of `Tractogram` in `Dataset` (`Dataview.from_hdf` needs a type dispatch; store `/data/<name>` as a group with `kind="tractogram"`); `htmlembed` inlining of `.bin` payloads (base64 in JSON) for single-file exports; `.trk/.tck` via `trx.io.load` (already works through trx-python — just tests + docs); per-group toggles and per-bundle colors from `dpg`; thick lines (instanced quads/tubes — r69 makes this non-trivial); endpoint projection onto the surface as a `Vertex` (`cortex.utils.get_vox_dist`-style KD-tree) for quickflat; Jupyter widget support (#608).

## Local verification workflow (user's machine, outside CI)
1. Worktree venv: `uv sync --all-extras` (or copy `cortex/*.so` from the main checkout per memory) and `uv pip install trx-python` (Python ≥ 3.11).
2. Data: `pip install pyAFQ` is heavy; instead download only the atlas zip (figshare id 11921522, md5 `b071f3e851f21ba1749c02fc6beb3118`) with `curl` after the user approves, unzip under `$TMPDIR`/a scratch dir, convert the 16 `.trk` files to one `.trx` (groups = bundle names) with trx-python. Untracked helper `.claude/launch_tracts.py` (modelled on `.claude/launch_viewer.py`: `server = cortex.webgl.show([vertex, tract], port=..., open_browser=False); server.join()`) pointing `cortex.db` at `~/repos/pycortex_store` and subject `fsaverage`, plus a `.claude/launch.json` entry so Claude can `preview_start` it and inspect the viewer in the built-in browser (rotate, toggle `surface_opacity`, check `window.viewer.tracts` in the console, read WebGL errors from the console log). Nothing from the store or the atlas is committed.
3. Browser-dependent tests are run by the user: `uv run pytest -p no:cacheprovider --no-cov cortex/tests/test_tractogram.py cortex/tests/test_webgl_tractogram.py cortex/tests/test_visual_regression.py -k "tract or opacity"`; regenerate references with `REGENERATE_REFERENCE_IMAGES=1` only after visual sign-off.
4. Before each PR: `uv run pytest` (full), `codespell`, `mypy cortex/dataset/tractogram.py`, `git diff --stat` sanity (no `overlays.svg`, no CRLF churn in `dataset.js`), one `pycortex-code-reviewer` pass. PRs are opened only after the user says so.
